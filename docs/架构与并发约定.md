# 架构与并发约定

P1 Label 使用单向状态流：SwiftUI 视图只提交用户意图，`AppModel` 在主执行器上维护编辑状态，独立服务负责文件、渲染和设备 I/O。新增功能应优先扩展对应服务，避免把协议、磁盘或图像处理重新放回视图。

## 分层

| 层 | 目录 | 职责 |
| --- | --- | --- |
| 应用与命令 | `P1Label/App` | 窗口、菜单和应用生命周期 |
| 界面 | `P1Label/Views`、`P1Label/Support` | 展示状态、收集输入、AppKit 小型桥接 |
| 状态模型 | `P1Label/Models` | 标签文档、选择、任务协调和用户偏好；独立维护撤销历史、打印历史、模板和吸附计算 |
| 文件与设备服务 | `P1Label/Services` | 原子读写、导入校验、USB/蓝牙连接、状态读取和更新检查 |
| 渲染 | `P1Label/Rendering` | 标签点阵、图片算法、打印几何和文本度量 |
| 协议桥 | `P1Label/P1USBBridge` | 最小化的 libusb C 接口 |

## 并发边界

- `AppModel`、`BluetoothPrinterController` 和界面状态固定在 `MainActor`，所有界面可观察值只在主执行器更新
- JSON、CSV、图片解码和原子文件写入由 `DocumentFileService` 在后台执行，`DocumentFileAccess` 串行协调自动保存与交互式文件操作
- 标签栅格化和批量打印数据生成由 `PrintJobBuilder` 在后台执行，并在发布结果前检查任务标识和取消状态
- USB 枚举、libusb 打开、状态读取和数据发送不占用主执行器；`P1USBTransport` actor 保证同一时间只有一项 USB 操作
- 蓝牙回调统一切回 `MainActor`，连接和写入都有超时，continuation 只能由集中收尾方法恢复一次
- 打印发送期间暂停设备探测和状态查询；失败或设备未就绪时保留待确认任务，允许用户重试
- `PrintHistoryStore` 只在主执行器维护任务元数据；重试点阵受 32 MB 总预算约束，不写入偏好或日志
- 诊断报告在后台原子写入，只接收预先脱敏的状态快照

## 数据与任务不变量

- 文件写入使用原子替换；交互式读写均可取消，旧任务不能覆盖较新的选择或文档
- 自动保存只更新保存快照，不覆盖打印机错误、发送进度等用户状态
- 打开文件时校验纸张和元素几何；标签、CSV 和图片均设有读取大小上限
- 打印数据在发送前完成尺寸预检；纸张、偏移和元素坐标必须是有限且受支持的值
- USB 与蓝牙传输不允许并发复用同一通道，忙碌时返回明确错误
- 文档切换时清空图片预览缓存，避免相同元素标识跨文档复用旧预览
- 新建、套用模板、打开和退出统一经过未保存更改协调；保存失败或取消不会继续破坏性操作
- 拖动开始时生成并排序一次吸附目标，拖动帧只执行二分邻近查找；位置和尺寸每帧合并为一次文档写入

## 兼容范围

- 仅维护当前 macOS 26、Apple 芯片和当前标签文档结构，不保留已无调用方的网页打印及旧图片抖动字段实现
- 文档缺少当前可选字段时使用安全默认值；已废弃字段会被忽略，不再改变当前行为
- IOKit 枚举与内置 libusb 是当前 P1 USB 发现和传输链路的一部分，不属于待删除的历史兼容代码

## 验证要求

提交前至少执行 `swift test` 和 `swift build -c release`。涉及应用打包时再运行 `./script/build_and_run.sh --package`，并验证应用签名、内置 libusb 链接和固定交付目录中的压缩包。
