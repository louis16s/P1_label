# 本地构建与交付规范

本仓库只使用一个本地交付位置：`artifacts/latest/`。无论通过 Codex 的 Run 按钮、终端运行还是打包，最新产物都覆盖写入这里。

| 位置 | 用途 | 是否提交 Git |
| --- | --- | --- |
| `P1Label/` | 应用源代码、资源和测试 | 是 |
| `script/build_and_run.sh` | 唯一构建、签名、打包、启动入口 | 是 |
| `artifacts/latest/P1Label.app` | 最新本地可运行应用 | 否 |
| `artifacts/latest/P1Label-macOS26-arm64.zip` | 与最新应用一致的交付压缩包 | 否 |
| `artifacts/archive/` | 整理目录时保留的历史本地产物 | 否 |
| `work/` | SDK 研究、临时素材和分析文件 | 否 |

## 常用命令

```sh
# 构建最新 Debug 应用并启动
./script/build_and_run.sh

# 构建并确认应用进程正常运行
./script/build_and_run.sh --verify

# 构建可交付的 Release 应用与 zip
./script/build_and_run.sh --package
```

每个命令都会刷新 `artifacts/latest/` 中的 `.app` 与 zip；不需要再从 `.build/`、`dist/` 或 `outputs/` 查找文件。

## 版本与发布

`VERSION` 是唯一的本地版本来源。普通提交不会修改它；只有明确决定发布新版本时才修改 `VERSION` 并创建对应的 `v*` 标签。GitHub Actions 使用同一套脚本：每次推送上传最新 zip 为构建产物，只有标签推送才创建 GitHub Release。

## 旧目录迁移

历史的 `dist/` 和 `outputs/` 不再作为交付入口。整理时其中的既有文件会移动到 `artifacts/archive/`，保留但不参与后续构建。
